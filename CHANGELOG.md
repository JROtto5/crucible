# Changelog

One line per change, newest first.

- 2026-11-06: The verifier can run Python the way it runs JS: the project's own `python3 -m unittest` / `pytest` and `python3 -c` probes (also `python`), with `PYTHONDONTWRITEBYTECODE=1` so no `__pycache__` lands in the checkout; a modified copy goes in a fresh temp dir. On the stored reviews only 5 of 149 Python findings were verified by running something (JS: 14 of 64) and 58 verifications had a run refused. Checked against the real CLI: unittest and `-c` run, `rm` is still refused. Reviewers and tool-less calls stay read-only.
- 2026-11-05: `crucible stats`: the real-PR precision log as a command, replacing the ad-hoc tally in the exchange notes. It reads the stored reviews offline and reports per project and overall: reviews, $/review, unique model findings kept or dropped by verification, and how the kept ones were answered (fixed / deferred / refuted / unanswered, latest answer wins). Findings are deduped across rounds by id (incremental carry) and by normalized title within a project (an amended commit's full re-review gives the same finding a new id); scanner/style output is left out. On the stored upstream reviews: 59 reviews ($0.79/review), 195 unique findings, 96 kept (92 low), 16 of 21 answered kept findings held up (5 refuted; 75 of the 96 are unanswered, so this is not overall precision). `--project`, `--include-self`, `--json`. Tests 115 → 117; the dedupe test fails if findings aren't grouped.
- 2026-11-05: Cost routing by change type, behind `--route` / `CRUCIBLE_ROUTE=1` (off by default). A round whose changed files are all docs or PR text (prose markup and README/LICENSE-style files; not `.txt` build files, code under `docs/`, agent instructions or prompt files) gets one cheaper pass (`claude-sonnet-5-5` reviews, verification stops at the cheap tier); code keeps the full pipeline. New `crucible routing-replay` replays the stored reviews offline and gates each rule: no important/critical finding lost, and no medium lost or downgraded. On the 57 stored upstream reviews ($0.81/review; review pass $0.44, verification $0.17; 51% of 195 model findings refuted), the docs rule matches 0 reviews (no evidence either way, so it stays opt-in). "Lows settled on the cheap tier" fails the bar: 4 real lows lost, one the author fixed (umu's "ruff is clean" claim), 6 refuted findings kept, refuted share 51% → 49%; with crucible's own reviews added it also loses a medium the author fixed. So it is not built. The replay's real finding: 38 of 57 reviews (67% of the spend, $30.90 of $46.15) were full re-reviews of an amended commit on a branch already reviewed on the same base, so incremental re-review never applied. Verifications now record their cost per tier, and each finding records the reviewer's own severity (`proposed_severity`), so later replays are exact. Tests 108 → 115. Self-review (5 rounds) fixed 9 findings, mostly docs-classifier edge cases, plus a routed round skipping the carried-finding re-check and `CRUCIBLE_ROUTE=false` turning routing on.
- 2026-11-05: CONTRIBUTING.md and GitHub issue templates (wrong finding, missed issue, bug). Each asks for the evidence that turns a report into a regression test (the finding block, the line or output that disproves it, `crucible --version`) and warns against pasting private code. The README links to it.
- 2026-11-05: `crucible eval` skips build output in fixture trees (`__pycache__`, `*.pyc`/`*.pyo`, `.pytest_cache`, `.ruff_cache`, `node_modules`). A local pytest run (before `pytest` was limited to `tests/`) had left a `.pyc` in `clean-py-fix-with-test`, and the case crashed with a UnicodeDecodeError instead of being scored. Tests 107 → 108.
- 2026-11-05: Absence findings no longer carry after they are fixed (ROADMAP item 1, seen 4 times in crucible's own rounds). "No test for the new recheck guard" cites the guard, but its test lands in the test file, so the guard's lines never change and the line-based carry kept it for 2 rounds. The reviewer now names `anchor_files` for a finding about something missing; such a finding (or one whose title says so: 40 of 331 real titles, checked by hand) is verified again, by the full tier chain and with the anchor's diff in the prompt, whenever its anchor changes (a named file that doesn't exist widens to its directory; a missing name means any change), and carried untouched otherwise. Changed paths are read with `-z`, so non-ASCII anchors match. A round whose review pass failed says so in its summary. An incremental round's summary covers only its own changes instead of repeating the earlier round's text about problems already fixed. Tests 103 → 107; the 4 new ones fail on the old code. Self-review: 3 rounds, 7 real lows fixed.
- 2026-11-05: Lint: `ruff check .` is clean (pyflakes and syntax rules, 7 unused imports removed) and runs in CI. `pytest` only collects `tests/`, not the eval fixture repos, so crucible's own detected checks pass on itself.
- 2026-11-05: Installable: `pipx install git+https://github.com/JROtto5/crucible` gives a `crucible` command, with no dependencies beyond the standard library (`pyproject.toml`, package `crucible-review`). The hand-written PYTHONPATH shim is no longer needed. The `reply` guide moved into the package (`crucible/guides/`) so an installed copy still has it, and `crucible eval` outside a git clone now says it needs one instead of finding zero cases. CI installs the package and runs `crucible --version` on every Python version. Tests 100 → 103.
- 2026-11-05: `crucible learn` skips bot-authored PRs (Dependabot, Renovate, any `[bot]` or `type: Bot` account) and bot comments when it measures house style and collects maintainer rules. On umu the Dependabot bodies had pushed the learned median to 879 words. Comment density and the code sample now come from the upstream default branch instead of the working tree, so your own unpushed commit is no longer quoted back as house style. Non-UTF-8 source files are read leniently, as before. Non-ASCII file names are sampled too (real-use bug j). Tests 94 → 100.
- 2026-11-05: Description checks measure only what the author wrote. "Length reads as generated" no longer counts the PR template's HTML comment, its checklist (ticked or not) or the title: the Heroic draft that was flagged at 348 words against a 132-word median is 226 words of prose (real-use bug g). "No testing evidence" accepts checked/confirmed/measured/reproduced, "tests pass", and a code span that is a build or test command with arguments, including chained (`cd docs && make html`) and env-prefixed ones; file and tool names (`yarn.lock`, `python`) don't count (bug m: "Checked with `npm run build-docs`" on three.js). Tests 88 → 94.
- 2026-11-05: New readiness item "no open PR changes the same lines" (warn only). The competing-PR check only read the linked issue's timeline, so it missed Heroic #5776, an open PR fixing a neighbouring issue in the same sort code (real-use bug k). Up to the 300 most recently updated open PRs are read (≤3 GraphQL calls); the 20 most focused that share a file have their patches compared line by line against the lines we change. Bots, our own PRs, lockfiles, changelogs and package.json are ignored; PRs that couldn't be compared are named, never passed. On the Heroic change it lists #5776 first, ahead of a 100-file rewrite. Tests 79 → 88.
- 2026-11-05: When the verifier reaches a verdict but every StructuredOutput call is rejected ("must have required property 'confidence'" although it was set; 5 of 415 verifications on 2026-11-04), its prose answer is transcribed into the verdict schema by one cheap, tool-less call instead of leaving the finding unverified (real-use bug l). A transcription is capped at medium confidence, so on the cheap tier it always escalates, and it is never cached. A transcribed "does not hold" never drops a finding: it stays unverified, with the prose as the reason. The report marks transcribed verdicts. Replayed on the 5 real failures: all 5 match the prose (3 keep, 2 drop), $0.004. Tests 71 → 79.
- 2026-11-04: A project check that fails naming an untracked file (an eslint crash on a scratch `.cjs` in the repo root, Heroic) is re-run on a clean checkout of HEAD and that result counts; the report and the reviewer's facts say so, and keep the working-tree tail (real-use bug h). Failures that name no untracked file are not re-run. The base and clean worktrees no longer fail with "File exists" when the commit tracks a `node_modules/` entry, and a monorepo package's `node_modules` is shared too (bug f). Tests 65 → 71.
- 2026-11-04: A rerun on an already-reviewed commit re-reviews when `PR_DRAFT.md` (or `--draft`) or the base changed, instead of returning the old verdict for a draft it never read; `--fresh` alone now redoes the review (real-use bug i). Editing only the author's notes keeps the verdict, and an unreadable draft is a clean error instead of a traceback. Tests run directly (`python tests/test_core.py`) run all 65, not the first 40.
- 2026-11-04: **v0.3.0.** `crucible eval`: 16 labelled fixture changes (12 planted bugs, 4 clean) scored for recall, false blocking findings, true findings dropped by verification, and cost; results in eval/RESULTS.md. Baseline: 92% blocking recall, 100% any-severity, 0 false blocking.
- 2026-11-04: Tiered verification: a cheap model checks each finding first, and the strong model re-checks survivors at blocking severity or low confidence. Same eval recall, 24% lower verification cost ($1.75 vs $2.30 on the eval set). `--no-tiers`, `CRUCIBLE_VERIFY_CHEAP`.
- 2026-11-04: Incremental re-review: only hunks changed since the branch's last complete review are reviewed; untouched findings are carried with remapped lines, touched ones are re-verified (so fixed bugs drop out). `--full` forces a full review.
- 2026-11-04: Stable verdicts: review/verification cache keyed on what results depend on, not volatile check output, so `--force` on the same commit reproduces the findings; `--fresh` bypasses the cache (real-use bug e).
- 2026-11-04: "issue linked" needs a linking keyword or an issue URL; a bare #N (often a PR) no longer counts, a linked PR fails "unclaimed", and template placeholders are reported (bug a). Monorepo check detection runs the touched packages' scripts in their directories (bug b). `polish` keeps required issue-link lines verbatim (bug c). `PR_DRAFT.polished.md` is never judged unless passed with `--draft` (bug d).
- 2026-11-04: Fixed `map_line` for pure insertion/deletion hunks; carried findings could land a line off.
- 2026-11-04: CI on GitHub Actions (unit tests, Python 3.10–3.13).

- 2026-11-04: Notes headings must open the heading, the review log says where the notes were cut, `prep` gets the submitted description and the notes separately, and inline ```code``` lines no longer open a fence.
- 2026-11-04: Draft splitting follows CommonMark fences, ignores a `## Body` inside the notes, keeps the preamble with the notes through `polish`, never duplicates the notes marker, and only flags headings against learned measurements (all found by crucible reviewing its own change).
- 2026-11-04: Judge only the submitted part of `PR_DRAFT.md`. The author's notes (a preamble before `## Body`, "Explain it to me", "Issue to file first", or anything after `<!-- crucible: notes -->`) no longer drive length, heading or issue-link findings, and `polish` no longer folds them into the body. Headings from the repo's PR template (emoji prefixes included) are no longer flagged as unusual.
- 2026-11-04: Send the model prompt on stdin; `--allowedTools` swallowed it as a tool name when no budget was set.
- 2026-11-04: `crucible waive` for readiness items that don't apply, with the reason shown in the report.
